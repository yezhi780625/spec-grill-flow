收到一份 PM 需求時,先把它重建成最強版本,再給出技術意見。順序不可顛倒:先 steelman,後評論。

## Steps

1. **挖出「為什麼」。** 需求文字通常是解決方案(「加一個彈窗」),不是目標(「新用戶流失前展示核心價值」)。從需求中推導背後的商業目標或用戶問題。若需求完全沒提供推導線索,列出 2-3 個最可能的目標假設,標明是假設。完成標準:寫出一句「這個需求真正想解決的問題是 ___」。

2. **Steelman。** 用最有說服力的方式陳述這個需求成立的理由:它解決什麼痛點、為什麼這個方案有它的優勢(實作速度、可測量性、風險低等)。寫到「如果我是提案人,這是我能講出的最好版本」為止——甚至比原文更清楚有力。完成標準:steelman 段落單獨成立時,讀起來像在支持這個需求。

3. **技術與產品意見。** 只有在 steelman 之後才提出:疑慮、edge cases、替代方案、成本估計。每個疑慮對應到 steelman 裡的某個論點——反駁的是最強版本,不是最弱版本。若 steelman 完發現需求其實站得住腳,直接說,把力氣放在幫它補完細節。

4. **確認句收尾。** Steelman 有腦補風險:重建出的目標可能不是 PM 真正的意圖。回覆結尾必須是一句開放的確認問句,例如「我理解的核心問題是 ___,對嗎?還是你考量的點是別的?」讓 PM 修正,而不是替他定案。

## Output format

依序輸出四段,用標題分隔:

> **需求背後的目標**(step 1)
> **這個需求最強的版本**(step 2)
> **我的意見**(step 3,每點標明對應哪個論點)
> 結尾一句確認問句(step 4,不加標題)

## Guardrails

- Steelman 是真的先假設「這個需求可能是對的」,而不是禮貌性複述後照樣否決的話術。若 step 3 的每一點都是否定,回頭檢查 step 2 是否寫得夠強。
- 語氣是協作者在幫 PM 把需求想完整,用「我們」而不是「你沒想到」。

## 串接:結論之後(team-workflow)

本 skill 是 team-workflow **分流之前**的目標確認站。它不裁決「該不該做」——那是產品決策,RD 通常沒有否決權,硬擋語義只會被繞過;它保證的是**目標確認完成,才寫 spec**。真實機制是說服而非否決權:一份好的 steelman 加上對最強版本的疑慮,常讓 PM 自行收斂或撤回需求——撤回也是攔截。唯一保留擋下語義的是內部自發 feature:RD 對自己團隊的提案有裁量權。

**只適用於提案**(要求新行為的需求),不適用於**回報**。判別式:對方期望的行為,spec(或現有明確行為)已描述了嗎?已描述 → 這是 bug 回報,目標自明,免本 skill 直接進分流(即快速通道的 bug fix);未描述 → 「這是 bug」其實是包裝成回報的需求變更,照跑本 skill。拿不準 → 跑,誤跑成本只是一則回覆。**內部自發的新 feature 同為提案**:由提案者以外的執行者(同事,或 fresh-context subagent)跑本 skill,提案者作答——提案的「依據」正是 step 1 要產出的目標。

以 PM 對 step 4 確認句的回覆定案目標(PM 不在開發環境時由 RD 向 PM 核對後代為轉達——是轉達,不是代拍板;目標寫入 spec 時標注確認方式)後:

- **目標已確認** → 進入 `team-workflow` 的**分流**。把定案後的「需求背後的目標」段落連同需求原文一起帶入——完整通道作為 Phase 1 `/speckit-specify` 的輸入,成為 spec 動機(motivation)段落的雛形;輕量通道則隨該條驗收標準的增修一併寫入 spec。「為什麼做」從第一天就寫在 spec 裡,Phase 2 grill 與 Phase 5 驗收都以此為基準。step 3 未被採納的疑慮不隨 PM 拍板蒸發——以「已知取捨」寫入 spec 的「未解事項」段,Phase 5 合併前逐項定案。
- **目標未獲確認** → 不寫 spec、不進分流。未經 PM 確認的目標不得寫進唯一真相源。
- **PM 經 steelman 後撤回或改寫需求,或內部提案被擋下** → 在 `specs/retro-log.md` 回填一行(通道記「攔下」、觸發條款記「steelman」、備註一句理由)——沒有 PR 的攔截不留這行就不可觀測;改寫後的新需求重新走一次本 skill。

分工邊界:steelman 確立「為什麼做」(目標與論證);Phase 2 的 grill 錘「怎麼做才驗收得了」(驗收標準可量測性、edge cases 與失敗路徑、需求矛盾、「不做什麼」)。過了 steelman 不代表免 grill,兩者維度不同,不可互抵。
